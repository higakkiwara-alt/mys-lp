# OTK COMPANY 経理引き継ぎシステム

美容室を複数店舗運営する OTK COMPANY の経理業務を、**特定の担当者の記憶や経験に依存しない状態**へ移行するためのシステムです。
Googleスプレッドシート + Google Apps Script (GAS) で動作し、書類の受付から処理完了・月次締め・引き継ぎまでを一元管理します。

> 📁 このフォルダは `mys-lp` リポジトリ内の独立したサブプロジェクトです。親フォルダのNext.jsアプリとは無関係に動作します。

---

## 1. このシステムでできること

- 16種類のシートを**ワンクリックで自動作成**(2回実行しても壊れない冪等設計)
- 書類の受付台帳・レシート管理・請求書管理・契約書管理・質問管理
- 管理IDの自動採番(`ACC-YYYYMM-0001` 形式、同時編集でも重複しない)
- 登録日時・更新日時・完了日・支払完了日の**自動記録**
- 重要項目の**変更履歴**の自動保存
- **データ不整合の自動検出**(期限超過・支払漏れ・原本未保存など15種類)
- 月次締めチェックリストの**毎月自動生成**(店舗ごと)
- 期限超過・確認待ち・緊急案件の**メール通知**
- 代表が一目で状況把握できる**ダッシュボード**
- Google Drive の経理フォルダ構成の自動作成
- 書類受付用 Google フォームの自動作成

## 2. 必要なもの

| もの             | 説明                                                |
| ---------------- | --------------------------------------------------- |
| Googleアカウント | スプレッドシート・Driveを使うアカウント(会社用推奨) |
| パソコン         | Windows / Mac どちらでも可                          |
| Node.js          | バージョン18以上(後述の手順でインストール)          |
| このリポジトリ   | `git clone` またはZIPダウンロード                   |

プログラミングの知識は不要です。以下の手順をそのまま実行してください。

## 3. Node.js の準備

1. https://nodejs.org/ja を開く
2. 「LTS(推奨版)」をダウンロードしてインストール
3. ターミナル(Windowsは「コマンドプロンプト」、Macは「ターミナル」)を開き、次を実行して数字が表示されればOK:

```bash
node --version
```

## 4. 依存パッケージのインストール

ターミナルでこのフォルダへ移動して実行します:

```bash
cd accounting-handover-system
npm install
```

## 5. clasp のログイン

clasp は Google Apps Script へコードを送るツールです。

```bash
npm run clasp:login
```

ブラウザが開くので、**会社のGoogleアカウント**でログインして許可してください。

> 初回は https://script.google.com/home/usersettings を開き、「Google Apps Script API」を**オン**にしてください(オフのまま push するとエラーになります)。

## 6. Google Apps Script プロジェクトの作成

**方法A(推奨・スプレッドシートに紐付ける)**

1. https://sheets.google.com で新しいスプレッドシートを作成(名前例: `OTK経理引き継ぎシステム`)
2. メニュー「拡張機能」→「Apps Script」を開く
3. 左の歯車(プロジェクトの設定)→「スクリプト ID」をコピー

**方法B(コマンドで作成)**

```bash
npm run clasp:create
```

## 7. .clasp.json の設定

```bash
cp .clasp.json.example .clasp.json
```

`.clasp.json` をメモ帳等で開き、`scriptId` に手順6でコピーしたスクリプトIDを貼り付けます。

> `.clasp.json` は `.gitignore` 済みです。**コミットしないでください**(セキュリティ)。

## 8. スプレッドシートIDの設定(通常は不要)

方法Aで作成した場合、スクリプトはスプレッドシートに紐付いているため設定不要です。
スタンドアロンのスクリプトから操作する場合のみ、後述の Script Properties に `SPREADSHEET_ID` を設定してください(スプレッドシートのURLの `/d/` と `/edit` の間の文字列)。

## 9. Script Properties の設定

Apps Script エディタ →「プロジェクトの設定」→「スクリプト プロパティ」で以下を追加します(**すべて任意**。未設定でも動きます):

| キー                     | 例                | 説明                                                          |
| ------------------------ | ----------------- | ------------------------------------------------------------- |
| `CEO_EMAIL`              | ceo@example.com   | 代表の通知先                                                  |
| `ACCOUNTING_EMAIL`       | keiri@example.com | 経理担当の通知先                                              |
| `TAX_ACCOUNTANT_EMAIL`   | tax@example.com   | 税理士(税理士確認待ち通知)                                    |
| `LABOR_CONSULTANT_EMAIL` | sr@example.com    | 社労士                                                        |
| `NOTIFICATION_ENABLED`   | true              | **通知を有効にする**(初期値は誤送信防止のため無効)            |
| `NOTIFICATION_HOUR`      | 8                 | 毎日の通知時刻(0-23)                                          |
| `DEADLINE_WARN_DAYS`     | 3                 | 支払期限の警告日数                                            |
| `CONTRACT_WARN_DAYS`     | 30                | 契約更新の警告日数                                            |
| `COMPANY_NAME`           | OTK COMPANY       | ダッシュボードの表示名                                        |
| `DRIVE_ROOT_FOLDER_NAME` | 経理管理          | Driveルートフォルダ名                                         |
| `MODE`                   | test              | `production` にすると本番モード(通知件名の [テスト] が外れる) |

> メールアドレスをコードに書かない設計です。必ずここで管理してください。

## 10. コードのビルド

```bash
npm run build
```

`dist/main.js` が生成されます(`src/` のTypeScriptを1ファイルにまとめたもの)。

## 11. clasp push(コードの反映)

```bash
npm run clasp:push
```

## 12. 初回実行

1. スプレッドシートを開き直す(リロード)
2. メニューに「**OTK経理管理**」が表示される
3. 「OTK経理管理」→「**初期セットアップ**」をクリック

## 13. 権限承認

初回実行時に「承認が必要です」と表示されます:

1. 「権限を確認」→ 自分のアカウントを選択
2. 「このアプリはGoogleで確認されていません」→「詳細」→「(プロジェクト名)に移動」
3. 「許可」をクリック

これは自分で作成したスクリプトに自分が許可を出すもので、安全です。
承認後、もう一度「初期セットアップ」を実行してください。全16シート+サンプルデータが作成されます。

## 14. カスタムメニューの使い方

| メニュー                 | 何をするか                                   | いつ使うか                        |
| ------------------------ | -------------------------------------------- | --------------------------------- |
| 初期セットアップ         | 全シート・書式・入力規則・トリガーを構築     | 最初に1回(何度実行しても安全)     |
| シート構成を修復         | 不足シート・不足列を追加                     | 誤って列を消したとき              |
| 入力規則を再設定         | プルダウンを最新のマスターで再構築           | 選択肢マスターを変更したとき      |
| 数式を再設定             | ダッシュボード数式・レシート重複判定を再計算 | 表示がおかしいとき                |
| 条件付き書式を再設定     | 警告色のルールを再構築                       | 色が表示されないとき              |
| 月次チェックリストを作成 | 指定年月の締めチェックリストを生成           | 手動で作りたいとき(毎月1日は自動) |
| データ不整合を確認       | 15種類の不整合を検出して16へ出力             | いつでも(毎日自動でも実行)        |
| ダッシュボードを更新     | 最終更新日時を更新                           | いつでも                          |
| Driveフォルダを作成      | 経理管理フォルダ構成を作成(既存は再利用)     | 初回と店舗追加時                  |
| 受付フォームを作成       | 書類受付Googleフォームを作成                 | 初回に1回                         |
| 通知テスト               | テストメールを送信                           | 通知設定の確認                    |
| サンプルデータを削除     | 備考が【サンプル】の行を削除                 | 本番運用開始時                    |
| システム設定を確認       | 現在の設定を表示                             | いつでも                          |

## 15. 店舗マスターの設定

`11_店舗・事業マスター` を開き、仮データ(「店舗A(仮・要変更)」など)を実際の店舗情報へ書き換えます:

1. 店舗名・法人名・所在地・管理責任者を入力
2. 稼働状況を「稼働中」にする(稼働中の店舗だけがプルダウンと月次チェックリストの対象)
3. 書き換えたら備考の「【サンプル】…」を消す(消さないと「サンプルデータを削除」で行ごと消えます)
4. メニュー「入力規則を再設定」を実行

## 16. 担当者マスターの設定

`12_担当者マスター` で仮データを実際の担当者へ書き換えます。「通知対象」にチェックした人へ通知メールが届きます。手順は店舗マスターと同じです。

## 17. 取引先マスターの設定

`10_取引先マスター` へ主要な取引先(材料商社・広告・家主・税理士等)を登録します。インボイス登録番号と通常の勘定科目候補を入れておくと入力が楽になります。

## 18. 通知先の設定

手順9の Script Properties でメールアドレスを設定し、`NOTIFICATION_ENABLED` を `true` にして、メニュー「通知テスト」で受信を確認してください。

## 19. Driveフォルダの作成

メニュー「Driveフォルダを作成」を実行すると、マイドライブに「経理管理」フォルダと配下の分類フォルダ(詳細は `docs/drive-folder-structure.md`)が作成されます。既存フォルダは再利用され、ファイルの移動・削除は一切行いません。

## 20. テストモードでの確認

初期状態は**テストモード**です(通知件名に [テスト] が付く)。以下を確認してください:

1. サンプルデータで台帳へ行を追加 → 管理ID・登録日時が自動入力される
2. ステータスを「処理済み」に変更 → 完了日が入る
3. メニュー「データ不整合を確認」 → 16へ結果が出る
4. 「通知テスト」→ メールが届く

## 21. 本番モードへの切り替え

1. メニュー「サンプルデータを削除」を実行
2. Script Properties の `MODE` を `production` に設定
3. `NOTIFICATION_ENABLED` を `true` に設定

## 22. 毎日の運用方法

- 書類を受け取ったスタッフ → 受付フォームまたは `02_書類受付台帳` へ登録(当日中)
- 経理担当者 → ダッシュボードの「未処理」「期限」を確認し、上から処理
- 判断に迷ったら → `07_確認・質問管理` へ登録(放置しない)
- 詳細: `docs/accounting-operation-manual.md`

## 23. 毎月の締め作業

毎月1日に当月分のチェックリストが自動生成されます。`08_月次締めチェックリスト` を上から順に完了させ、進捗はダッシュボードの「月次締め進捗率」で確認できます。

## 24. よくあるエラー

`docs/troubleshooting.md` を参照してください。代表例:

- メニューが出ない → ページをリロード。それでも出なければ `npm run clasp:push` を再実行
- 「承認が必要です」→ 手順13を実施
- 通知が届かない → `NOTIFICATION_ENABLED=true` とメールアドレス設定を確認し「通知テスト」
- `clasp push` が403 → Apps Script API をオンにする(手順5の注記)

## 25. 元に戻す方法

- スプレッドシート全体: ファイル → 版の履歴 → 変更履歴を表示 → 戻したい時点を選択
- 個別の値: `14_変更履歴` シートで変更前の値を確認して手で戻す
- セットアップのやり直し: 「初期セットアップ」は既存データを消さないため何度でも安全に実行可能

## 26. バックアップ方法

- 月1回: ファイル → コピーを作成(名前に年月を付ける)し、Driveの `99_保管・過年度` へ
- 版の履歴は自動保存されますが、コピーによるバックアップを併用してください

## 27. 税理士へ確認する事項

勘定科目・税区分はすべて「候補」であり、**このシステムでは確定しません**。
`docs/tax-accountant-confirmation-list.md` の一覧を顧問税理士に確認し、回答を `06_書類処理ルール` へ反映してください。

## 28. セキュリティ上の注意

- `.clasp.json`・APIキー・パスワードは**絶対にコミットしない**
- パスワードそのものをシートに書かない(保管場所の名前だけを書く)
- 共有は必要最小限の人に、必要最小限の権限で(`docs/permission-design.md`)
- 原本(紙・PDF)は勝手に捨てない。システムもファイルの削除・移動は行いません
- 税務判断・支払実行は必ず人間(代表・税理士)が行います

## 28.5 外部連携(Phase 2)

以下の自動化が追加されています。**すべて任意機能**で、設定しない連携は自動的にスキップされます。設定方法は `docs/integration-guide.md` 参照。

| 機能             | 設定キー                     | 内容                                                                    |
| ---------------- | ---------------------------- | ----------------------------------------------------------------------- |
| Gmail請求書取込  | `GMAIL_IMPORT_ENABLED=true`  | 添付付き請求書メールをDrive保存+台帳へ自動登録(毎日)                    |
| Square売上取得   | `SQUARE_ACCESS_TOKEN`        | 日次売上を店舗別に `17_売上データ取込` へ(毎日)                         |
| 明細CSV取込      | 不要                         | `04_銀行・カード明細/取込待ち` のCSVを `18_明細取込` へ                 |
| ファイル分類提案 | 任意で `VISION_API_KEY`(OCR) | 未分類ファイルの分類・命名を「提案」。**移動は承認後のみ**              |
| 仕訳候補CSV出力  | 不要                         | 月次の仕訳候補CSVを生成(freee/MFのインポート用)                         |
| 月次経営レポート | 不要                         | 店舗別の売上・経費・粗利を `19_店舗別月次集計` へ+代表へメール(毎月2日) |
| n8n Webhook      | `N8N_WEBHOOK_URL`            | 通知をJSONでn8nへ送信(LINE/Slack中継用)                                 |

メニュー「OTK経理管理」→「外部連携(Phase 2)」から手動実行もできます。
Phase 2 では OAuth スコープに Gmail読み取り・外部リクエストが追加されているため、`clasp push` 後の初回実行時に**再承認**が必要です。

## 29. n8n連携の将来構想

各シートは「1行=1レコード+一意の管理ID」で設計されており、n8n の Google Sheets ノードでそのまま読み書きできます。想定シナリオ: Gmail添付請求書の自動受付 → 台帳へ追記 → Slack/LINE通知 → 会計ソフトAPIへ連携。詳細は `docs/accounting-handover-design.md` の「将来連携」参照。

## 30. 会計ソフト連携の将来構想

`会計ソフト入力状況` 列で入力漏れを管理する現運用から、将来は freee / マネーフォワード等のAPIで仕訳候補を自動作成する構想です。勘定科目候補・税区分候補・インボイス登録番号の列はそのマッピングを見据えた設計になっています。
