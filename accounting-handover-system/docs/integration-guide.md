# 外部連携ガイド(Phase 2)

Phase 2 で追加された自動化機能の設定・運用ガイドです。
**すべて任意機能**です。設定しない連携は自動的にスキップされ、基本機能には影響しません。
認証情報(トークン・APIキー)は必ず Script Properties で管理し、コード・シートに書かないでください。

## 全体像

| 機能               | 必要な設定                            | 実行方法                           |
| ------------------ | ------------------------------------- | ---------------------------------- |
| Gmail請求書取込    | `GMAIL_IMPORT_ENABLED=true`           | 毎日自動+メニュー                  |
| Square売上取得     | `SQUARE_ACCESS_TOKEN`                 | 毎日自動+メニュー                  |
| 明細CSV取込        | なし(フォルダにCSVを置くだけ)         | 毎日自動+メニュー                  |
| ファイル分類提案   | なし(OCRは`VISION_API_KEY`で精度向上) | 毎日自動(提案のみ)+メニュー        |
| ファイル分類の実行 | なし                                  | **メニューのみ(人間の承認が必須)** |
| 仕訳候補CSV出力    | なし                                  | メニュー                           |
| 月次経営レポート   | なし                                  | 毎月2日自動+メニュー               |
| n8n Webhook通知    | `N8N_WEBHOOK_URL`                     | 通知送信時に自動                   |

日次同期(`jobIntegrationSync`)は通知時刻の2時間後に実行されます。

## 1. Gmail請求書の自動受付

**何をするか**: 検索条件に一致するメールの添付(PDF/画像)を Drive `00_未分類・新規受付` へ保存し、`02_書類受付台帳` へ「未確認」で登録。処理済みメールは `21_Gmail取込` に記録され二重取込されません。

**設定**:

1. Script Properties に `GMAIL_IMPORT_ENABLED` = `true`
2. 必要なら `GMAIL_SEARCH_QUERY` を変更(既定: `has:attachment (請求書 OR 請求 OR invoice OR 御請求) newer_than:30d`)
   - 例: 特定ラベルだけ対象 → `label:経理 has:attachment newer_than:30d`

**注意**: メールの既読化・ラベル変更・削除は行いません。スクリプトを実行するアカウントのメールボックスが対象です(経理用アカウントでの運用を推奨)。取込は1回あたり最新20スレッドまで(毎日実行されるため実用上十分)。

## 2. Square売上の自動取得

**何をするか**: Square Payments API から完了済み支払を取得し、日付×店舗で集計して `17_売上データ取込` へ書き込みます(同じ日付×店舗は上書き更新=冪等)。

**設定**:

1. https://developer.squareup.com/apps でアプリを作成し、**Production の Access Token** を取得
2. Script Properties に `SQUARE_ACCESS_TOKEN` を設定(テストは `SQUARE_ENVIRONMENT=sandbox`)
3. `11_店舗・事業マスター` の「Square店舗名」列に、Squareの店舗(ロケーション)名を正確に入力 → 店舗名に自動変換されます

**重要**: 取得されるのは管理用の概算です。**会計上の売上計上方法(総額か手数料控除後か、計上日)は税理士確認必要**です。

## 3. 銀行・カード明細のCSV取込

**何をするか**: Drive `経理管理/04_銀行・カード明細/取込待ち` に置いたCSVを解析し、`18_明細取込` へ追記します。主要な列名の揺れ(日付/取引日/ご利用日、出金/お引出額/ご利用金額など)とShift_JISに対応。同じ内容は取込キー(内容ハッシュ)で重複防止。

**運用**:

1. 銀行・カード会社のサイトから明細CSVをダウンロード
2. `取込待ち` フォルダへアップロード(ファイル名に「カード」「VISA」等が含まれると種別=クレジットカードと推定)
3. 翌日の自動実行を待つか、メニュー「明細CSVを取り込む」を実行
4. `18_明細取込` で台帳・請求書と突合し、「突合済み」+関連管理IDを記録

**制限**: 国内銀行に共通のAPIが無いため、CSVダウンロードは手動です(理由と代替案: 将来は電子帳簿保存法対応のアグリゲーションサービスや n8n 経由での自動取得を検討)。元のCSVファイルは削除・移動しません。

## 4. ファイル分類提案 + レシートOCR

**何をするか**:

- 提案: `00_未分類・新規受付` のファイルを解析し、`20_ファイル分類提案` に「推定書類種別・提案フォルダ・提案ファイル名(命名規則準拠)・推定日付/金額/購入先」を書き込みます。**この時点でファイルは一切動きません。**
- 実行: 人間が提案行を確認してステータスを「承認」にし、メニュー「承認済みのファイル分類を実行」を実行すると、移動+改名されます。エラー時は「エラー」列に理由が残ります。

**OCR設定(任意・精度向上)**:

1. Google Cloud で Vision API を有効化し、APIキーを作成
2. Script Properties に `VISION_API_KEY` を設定
3. 未設定でもファイル名ベースで分類提案は動作します

**制限**: Vision同期APIの仕様上、**PDFのOCRは非対応**(画像 JPEG/PNG等のみ)。PDFはファイル名で推定されます。代替案: レシートは写真(画像)で登録する運用を推奨。

## 5. 仕訳候補CSVエクスポート(会計ソフト連携)

**何をするか**: 指定年月のレシート・請求書から仕訳候補CSV(日付・金額・勘定科目候補・税区分候補・取引先・摘要・店舗・インボイス番号・管理ID)を生成し、Drive `10_月次締め/YYYY-MM` へ保存します。

**運用**: freee・マネーフォワードのインポート画面で列をマッピングして取り込んでください。**会計ソフトへの自動登録は行いません**(仕訳の確定は人間+税理士。設計原則)。

**将来構想**: freee API(OAuth)による仕訳候補の直接連携。現在のCSV列構成はそのままAPIペイロードに転用できる設計です。

## 6. 月次経営レポート・店舗別損益

**何をするか**: 毎月2日に前月分を自動集計(手動も可)。`17_売上データ取込`(売上)、`03_レシート`(経費)、`04_請求書`(経費)を店舗×月で集計し、`19_店舗別月次集計` へ洗い替え書き込み+代表へメール送信します。

**注意**: 管理会計用の概算です(発生主義の厳密な損益ではありません)。税務上の数値は税理士が確定します。

## 7. n8n Webhook通知

**何をするか**: メール通知と同時に、`N8N_WEBHOOK_URL` へ JSON を POST します。n8n 側で LINE / Slack / Chatwork などへ中継できます。

**設定**: n8n で Webhook ノードを作成し、そのURLを Script Properties `N8N_WEBHOOK_URL` に設定。

**ペイロード例**:

```json
{
  "source": "otk-accounting-handover-system",
  "event": "notification",
  "mode": "production",
  "title": "期限超過の案件があります",
  "count": 2,
  "sentAt": "2026-07-13 08:00:00",
  "items": [
    {
      "manageId": "ACC-202607-0001",
      "content": "...",
      "deadline": "2026-07-15",
      "assignee": "経理担当"
    }
  ]
}
```

書類の全文・添付は送信しません(機微情報保護)。

## セキュリティ上の注意(Phase 2)

- トークン・APIキーは Script Properties のみ。シート・コード・Gitに書かない
- Gmail取込は読み取りのみ(メールを変更しない)
- ファイル移動・改名は人間の「承認」後のみ。削除は一切しない
- 外部送信(Webhook)は件名・件数・ID・期限のみ。内容全文は送らない
- Square/Visionの権限は最小(読み取り用トークン・APIキー制限を推奨)
