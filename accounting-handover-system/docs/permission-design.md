# 権限設計

## 前提と制約(重要)

Googleスプレッドシートには**行単位・ユーザー単位の完全なアクセス制御機能がありません**。Apps Script でも「特定ユーザーに特定の行だけ編集させ、他は見せない」ことは実現できません。
そのため本システムは以下の3層で権限を実現します:

1. **共有設定**(スプレッドシート/Drive の共有機能) — 最も強い制御
2. **シート保護**(警告表示) — 誤操作防止。悪意ある編集は防げない
3. **運用ルール + 変更履歴** — 誰が何を変えたかを `14_変更履歴` で追跡できる状態にする

「見せない」制御が必要な範囲(例: 給与)は、このスプレッドシートに載せず別ファイルで管理してください。

## 役割別権限

| 役割         | スプレッドシート共有   | できること                                                                   | できないこと                                                    |
| ------------ | ---------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 一般スタッフ | **共有しない**         | 受付フォームからの登録のみ。自分の登録内容の確認はフォームの回答コピーで行う | シートの閲覧・編集/マスター・履歴の編集                         |
| 店舗責任者   | 閲覧者(必要なら編集者) | 自店舗の書類確認・不備修正・担当者割り当て                                   | 支払承認/マスター・設定の変更                                   |
| 経理担当者   | 編集者                 | 台帳・支払状況・会計入力状況の更新、質問登録、マスターの一部編集             | 代表承認列の入力/保護シートの編集(警告を無視しない運用)         |
| 代表         | 編集者(またはオーナー) | 全データ閲覧、代表承認、設定変更、担当者変更                                 | —                                                               |
| 税理士       | **原則: 閲覧者**       | 税理士確認対象の確認、Drive `09_税理士共有` の閲覧                           | 直接編集(編集させる場合は代表判断でコメント可→編集者へ段階的に) |

## シート保護(スクリプトが自動設定・警告表示)

| シート                                                    | 保護 | 理由                                     |
| --------------------------------------------------------- | ---- | ---------------------------------------- |
| 01_経理ダッシュボード                                     | ○    | 数式破壊の防止                           |
| 10_取引先/11_店舗・事業/12_担当者/13_設定・選択肢マスター | ○    | プルダウンの供給源。変更は経理責任者のみ |
| 14_変更履歴/15_システムログ                               | ○    | 監査証跡。追記はスクリプトのみ           |

「警告表示」保護のため編集自体は可能です(警告ダイアログが出る)。**警告が出たら編集をやめて経理責任者へ確認**する運用としてください。より強固にする場合は、シート保護の編集許可ユーザーを代表のみに手動変更できます(スクリプトは他人の権限を勝手に制限しません)。

## Drive の権限

`drive-folder-structure.md` 参照。要点: スタッフには `00_未分類・新規受付` のみ共有、税理士には `09_税理士共有` のみ閲覧共有。

## 承認の統制

- 支払の承認: `04_請求書・支払管理` の「代表承認」列。**代表以外は入力しない**(変更履歴で追跡可能)
- 承認基準額: 代表と経理責任者で決定し、`06_書類処理ルール` の請求書カテゴリに明記する
- 承認権限の有無は `12_担当者マスター` の「承認権限」列で宣言的に管理

## アカウント運用

- 共有は個人アカウント単位で行い、共用アカウントを作らない(変更履歴の実効性のため)
- 退職・異動時: 共有解除 → `12_担当者マスター` の稼働状況を「退職」へ(行は削除しない)
- オーナー権限は代表(または法人の管理アカウント)が保持する
