# 経理引き継ぎシステム 設計書

## 背景

OTK COMPANY は美容室を複数店舗運営しており、レシート・請求書・契約書・行政書類・売上資料(Square/ホットペッパービューティー/楽天ビューティー)など多種の経理書類が、複数の場所・形式で管理されてきた。処理方法の多くが特定の経理担当者の記憶と経験に依存しており、担当者交代時に業務が止まるリスクがある。

## 目的

経理担当者が交代しても、**スプレッドシートと運用マニュアルを見れば誰でも判断・処理できる**状態を作る。

- この書類は何か/どの法人・店舗に関係するか
- 何を処理し、どこに保存し、誰に報告・承認を仰ぐか
- 期限はいつか/処理済みか/会計ソフト・税理士への連携は済んだか
- 判断できないとき誰に質問するか

## 現状課題

1. 書類の保管場所・処理手順が属人化している
2. 期限(支払・契約更新・行政手続)の管理が個人任せ
3. 処理済み/未処理の状態が見えない
4. 法人と個人事業の書類が混在し区分が曖昧
5. 税理士・社労士への共有漏れが発生しうる

## 解決方針

- **台帳中心主義**: すべての書類はまず台帳(スプレッドシート)に載せる。「捨てない・放置しない・台帳に載せる」
- **ルールの明文化**: 書類カテゴリごとの処理方法を `06_書類処理ルール` に記録し、質問→回答→ルール化のループで育てる
- **自動化は補助**: ID採番・日時記録・不整合検出・通知・チェックリスト生成を自動化し、**判断(税務・支払実行)は人間に残す**
- **冪等な自動構築**: シート構成はコードで定義し、いつでも安全に再構築・修復できる

[経理担当] ──直接入力──────┤

              │  03_レシート管理    │   Apps Script
              │  04_請求書・支払    │ ← ・ID自動採番

              │  07_質問管理        │   ・変更履歴(14)

## データの流れ

### 書類受付から処理完了まで

1. **受付**: スタッフがフォームまたは台帳へ登録 → 管理ID・登録日時が自動付与
2. **分類**: 経理担当者が `06_書類処理ルール` を参照して種別・店舗・期限・勘定科目候補を入力
3. **保存**: 原本をルール記載のDriveフォルダへ保存し、リンクを台帳へ貼る(提案ファイル名: `YYYYMMDD_店舗_取引先_種別_金額_管理ID`)
4. **承認**: 必要に応じ「代表確認待ち」等のステータスで承認を待つ
5. **支払**(請求書): 04で支払予定→支払済み。支払完了日が自動記録され、支払証明リンク必須(不整合検出対象)
6. **会計入力**: 会計ソフトへ入力し「入力済み」へ(入力日が自動記録)
7. **完了**: ステータス「処理済み」→ 完了日が自動記録

### 質問からルール化まで

1. 判断できない事項を `07_確認・質問管理` へ起票(確認先: 代表/税理士/社労士…)
2. 回答を記録(回答日は自動)
3. 「ルール化の要否=要」の回答は `06_書類処理ルール` へ反映
4. 反映漏れは不整合検出とダッシュボードで可視化される

### 月次締めフロー

1. 毎月1日にトリガーが当月分のチェックリストを自動生成(店舗項目×稼働店舗+全社項目)
2. 担当者が各項目を「完了」に更新(完了日は自動)
3. ダッシュボードに進捗率が表示され、期限超過は毎日の通知対象
4. 「月次締め完了」項目の完了をもって締めとする

## 内部統制

- **職務分離**: 登録者・処理担当者・確認者・承認者(代表)を列で分離して記録
- **証跡**: 重要項目の変更は `14_変更履歴` に自動記録(追記専用・保護)
- **牽制**: 支払済みなのに支払証明が無い、処理済みなのに原本が無い等を毎日自動検出
- **原本保護**: システムはファイルの削除・移動・改名を行わない
- **人間の最終承認**: 税務判断・支払実行・ファイル削除は自動化しない(設計原則)

## 権限設計

`permission-design.md` 参照。要点: スプレッドシートの保護は「警告」レベル+運用ルールの組み合わせ。**行単位・ユーザー単位の完全な権限制御はスプレッドシートの仕様上不可能**であり、その制約を明記した上で、閲覧専用共有・シート保護・IMPORTRANGEによる税理士向け抽出で補う。

## エラー処理

- すべてのメニュー処理・トリガーは try/catch で保護し、`15_システムログ` へ記録
- セットアップは部分失敗しても続行し、最後に成功/失敗を報告
- LockService は finally で解放保証
- トリガーはハンドラー名で重複作成を防止
- シート・列が無い場合は「シート構成を修復」で自己修復可能
- 設定不足(通知先未設定等)は分かりやすい日本語エラー
