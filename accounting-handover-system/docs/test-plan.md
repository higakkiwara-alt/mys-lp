# テスト計画

## 1. 自動テスト(ローカル・Vitest)

Apps Script 固有機能(SpreadsheetApp 等)はローカルで実行できないため、判断ロジックを**純関数として分離**し単体テストしています。GAS依存部分は薄いラッパーに留めています。

```bash
npm run test     # 54テスト
npm run verify   # lint + test + build
```

| テストファイル                      | 対象           | 主な確認項目                                                                                                |
| ----------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `tests/idService.test.ts`           | ID採番         | 月内連番/月替わりリセット/プレフィックス分離/不正ID無視/通し番号形式                                        |
| `tests/helpers.test.ts`             | 汎用関数       | 日付変換/列文字/重複判定キー/提案ファイル名(禁止文字・長さ制限)                                             |
| `tests/validationService.test.ts`   | 不整合検出     | 15種の不整合の検出条件・非検出条件(完了日なし/支払証明なし/期限超過/ID重複/マスター不一致/ルール未反映など) |
| `tests/monthlyCloseService.test.ts` | 月次生成       | 店舗×項目の生成数/重複生成なし(冪等)/年またぎ期限/進捗率                                                    |
| `tests/dashboardService.test.ts`    | 集計定義       | 未処理カウント定義とQUERY用正規表現の一致                                                                   |
| `tests/dataIntegrity.test.ts`       | 重複防止・通知 | 不整合キーの一意性/通知本文の要件(件数・ID・期限・URL)/通知重複キー/リマインド抽出                          |

ビルド後のスモークテスト(`node -e` でGASグローバルをスタブし、バンドルが全20個の公開関数を globalThis へ登録することを確認)は開発時に実施済み。

## 2. 手動テスト手順(Google環境・受け入れテスト)

初回導入時に以下を順に確認してください。仕様書の完了条件に対応しています。

### セットアップ・冪等性

1. [ ] 「初期セットアップ」実行 → 16シート+90が作成され、サンプルデータが入る
2. [ ] **もう一度**「初期セットアップ」実行 → シート・ヘッダー・サンプル・マスター値が重複しない
3. [ ] 任意のシートに手入力したデータがセットアップ再実行後も残っている
4. [ ] 「Driveフォルダを作成」を2回実行 → フォルダが重複しない

### 自動採番・日時

5. [ ] `02_書類受付台帳` の新しい行に書類名を入力 → 管理ID(ACC-YYYYMM-nnnn)・受付日・登録日時が自動入力
6. [ ] 同じ行を編集 → 最終更新日時が更新される
7. [ ] 2人(または2タブ)で同時に行を追加 → IDが重複しない

### ステータス連動

8. [ ] 台帳のステータスを「処理済み」→ 完了日が入る。「未処理」に戻しても完了日は消えない
9. [ ] `04` の支払状況を「支払済み」→ 支払完了日が入る
10. [ ] `03` の会計ソフト入力状況を「入力済み」→ 入力日が入る
11. [ ] `07` に回答内容を入力 → 回答日が入る

### プルダウン・重複検出

12. [ ] 対象店舗のプルダウンに店舗マスターの店舗が出る(店舗を追加→即反映)
13. [ ] 担当者・取引先・ステータス・重要度のプルダウンが機能する
14. [ ] `03` に同じ 利用日+購入先+金額+利用者 の行を2つ入力 → 両方が赤くなる(重複候補TRUE)

### 不整合・ダッシュボード

15. [ ] 支払期限を昨日にした未払い請求を作成 → 「データ不整合を確認」で期限超過が16に出る
16. [ ] 同チェックをもう一度実行 → 同じ不整合が重複登録されない
17. [ ] 請求を支払済み+完了日+証明リンクありに直して再実行 → 対応状況が「解消済み」になる
18. [ ] ダッシュボードの「未処理件数」が台帳の未完了行数と一致する
19. [ ] 月次締め進捗率が (完了件数/当月件数) と一致する

### 月次チェックリスト

20. [ ] 「月次チェックリストを作成」で翌月分を生成 → 店舗数×8+12件が生成される
21. [ ] 同じ年月でもう一度実行 → 「作成済みです」と出て重複しない

### 変更履歴・通知

22. [ ] `04` の請求金額を変更 → `14_変更履歴` に変更前後が記録される
23. [ ] 100行の一括貼り付けをしても処理が完了する(onEditが数秒で終わり、無限ループしない)
24. [ ] 「通知テスト」でメールが届く(`NOTIFICATION_ENABLED=true` 設定後)
25. [ ] `NOTIFICATION_ENABLED` 未設定で「通知テスト」→ 設定方法を示すエラーメッセージが出る

### フォーム

26. [ ] 「受付フォームを作成」→ フォームURL表示。テスト回答を送信 → `02_書類受付台帳` に整形されて登録される

### 外部連携(Phase 2・設定済みの機能のみ)

27. [ ] 「Gmail請求書を取り込む」→ 対象メールの添付がDriveへ保存され、台帳と21に登録される。**もう一度実行しても同じメールは二重登録されない**
28. [ ] 「Square売上を取得」→ 17に日次行が入る。再実行で行が重複せず更新される
29. [ ] 明細CSVを「取込待ち」へ置いて「明細CSVを取り込む」→ 18に明細が入る。同じCSVを再取込しても重複しない
29-2. [ ] 明細取込後に「明細の突合候補を検索」→ 金額一致+日付近接の行が「候補あり」になり、関連管理IDと備考に候補が入る
30. [ ] 「ファイル分類を提案」→ 20に提案が入り、**ファイルは移動していない**ことを確認
31. [ ] 提案を「承認」にして「承認済みのファイル分類を実行」→ ファイルが提案フォルダへ移動・改名される
32. [ ] 「仕訳候補CSVを出力」→ 10_月次締め/YYYY-MM にCSVが生成される
33. [ ] 「月次経営レポートを作成」→ 19に店舗別集計が入り、通知メールが届く
34. [ ] `N8N_WEBHOOK_URL` 設定後に「通知テスト」→ n8n側でWebhook受信を確認

## 3. 回帰テスト

コード変更時は必ず `npm run verify` を実行し、上記の手動テスト 1・2・5・8・15 を最低限再確認してください。
