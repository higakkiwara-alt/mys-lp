# AI_ROUTER — ClaudeとCodexの役割分担方針

AI Bridgeにおける「どちらのAIに何を任せるか」の基本方針。
Claude Codeはタスクを受けたとき、まずこのファイルの方針に従って振り分ける。

## 役割分担

| 領域 | 主担当 |
|---|---|
| 経営判断・意思決定の整理 | Claude |
| 人間関係・コミュニケーション文面 | Claude |
| 教育思想・カリキュラム構成 | Claude |
| 文章構成・原稿執筆・要約 | Claude |
| コード実装・スクリプト作成 | Codex |
| 技術検証・動作確認・テスト | Codex |
| コードレビュー・セキュリティ指摘 | Codex |
| **最終統合・品質判断** | **Claude(必ず)** |

## ルール

1. **Claudeが最終統合する。** Codexの回答はそのまま正式成果物にしない。
2. **正式保存前に必ず waiting_approval へ置く。** 正式フォルダへの自動反映は禁止。
3. **外部送信は禁止。** メール・SNS・外部アップロードは行わない。
4. **Codexを呼ぶ必要がない簡単な文章作業では呼ばない。** 呼び出しはコスト。
5. **技術的検証やコードレビューが必要な場合だけCodexへ渡す。**
6. **同じ作業をClaudeとCodexで重複実行しすぎない。** 役割を分けてから依頼する。
7. **実行ログを残す。** すべての実行は tasks/<ID>/task.json と logs/ に記録される。
8. **元ファイルは変更しない。** 入力はコピーして扱う。
9. **秘密情報(APIキー・トークン)をMarkdownやログへ平文保存しない。**
10. **失敗時に再試行しすぎない。** ネットワーク系エラーのみ最大1回再試行。

## Codexへ渡す判断フロー

```
依頼を受ける
  └─ コード・技術検証・レビューが必要?
       ├─ いいえ → Claude単独で処理 → waiting_approvalへ
       └─ はい  → run_ai_bridge.py でタスク作成
                   → Codexへ指示 → 回答回収
                   → Claudeが統合 → waiting_approvalへ
```
