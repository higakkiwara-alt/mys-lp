# 07. Dashboard 設計(要件⑦)

`/dashboard/router` として既存ダッシュボードに追加。データ源は RouterRun / RouterStep テーブル(01参照)。

## 1. 表示項目

| セクション | 内容 | 集計 |
|---|---|---|
| **AI使用量** | モデル別呼び出し回数・入出力トークン(日/週/月) | RouterStep group by model |
| **コスト** | 日次/月次コスト、モデル別内訳、**Fable 5 日次上限の消化率バー**、月額予測 | costUsd 集計 + 上限は設定値 |
| **実行時間** | パイプライン所要時間(平均/p95)、ステップ別ボトルネック | durationMs |
| **成功率** | 実行成功率、ステップ別・Agent別・プロンプト別成功率 | status 集計 |
| **エラー** | 直近エラー一覧(原因・発生ステップ・リトライ結果)、承認待ちキュー | status=error / waiting_approval |
| **改善案** | 週次で Reviewer Agent が自動生成(下記) | 週次バッチ |

## 2. 改善案の自動生成(Reviewer Agent)

週次 cron で直近ログを Sonnet に渡し、以下の観点で改善提案を生成して表示 + Obsidian に保存:

- コスト: 「この用途は Haiku に降格可能(推定 -$X/月)」
- 品質: 「プロンプト sns-instagram-post v3 の成功率が80%未満 → 改善案」
- 運用: 「承認待ち滞留が平均6時間 → 通知方法の変更提案」
- 拡張: 「同種の手動依頼が週5回 → n8n ワークフロー化の提案」

## 3. リアルタイム性

- 一覧・集計: ページロード時 + 30秒ポーリング(既存 dashboard と同じ `@tanstack/react-query` パターン)
- 実行中パイプラインのステップ進行: 実行詳細ページで 5秒ポーリング(Phase2 で SSE 化)

## 4. 画面構成

```
/dashboard/router
├── サマリーカード(今日のコスト / 実行数 / 成功率 / Fable 5 残量)
├── コスト推移グラフ(30日、モデル別積み上げ)※recharts(導入済み)
├── 実行履歴テーブル(フィルタ: 状態/Agent/モデル)→ 詳細(ステップタイムライン)
├── 承認待ちキュー(承認/却下ボタン → /approve API)
└── 改善案フィード(週次生成分)
```
