# 06. n8n ワークフロー設計(要件⑥)

定型・イベント駆動の自動化は n8n が担当。判断が必要な箇所だけ Router(API)を呼ぶ。

## 1. 役割分担

| | 担当 |
|---|---|
| 判断・生成(何を作るか、どう書くか) | AI Router OS(本体) |
| 定型フロー・スケジュール・外部サービス連携 | **n8n** |

n8n からは `POST /api/router/intake` を呼ぶだけ。逆に Router のパイプラインの `sns` 等のステップは n8n の webhook を呼ぶ。相互に疎結合。

## 2. ワークフロー一覧(全体設計)

### WF-1: 音声メモ → 知識化(要件の例)

```
音声(スマホ録音 → Google Drive / LINE 音声)
→ [n8n] 新ファイル検知
→ 文字起こし(Whisper API)
→ [Router] 要約 + 知識化(Sonnet: 要点・決定事項・TODO抽出)
→ Obsidian 保存(Meeting/ or Daily Note、タグ・リンク自動)
→ [Router] AIレビュー(Reviewer Agent: 発信価値があるか判定)
→ (価値あり)SNS 下書き生成 → 承認待ち
→ (承認後)各SNSへ予約投稿
→ (Phase2)動画化(台本→動画生成AI)
→ 保存 + report(LINE通知)
```

### WF-2: SNS 予約投稿

```
[Router] sns ステップ(承認済み)→ webhook
→ [n8n] 媒体別に整形済み本文+画像を受領
→ Instagram Graph API / LINE公式 / X / YouTube へ予約投稿
→ 投稿結果(成功/失敗/URL)を Router にコールバック → report
```

### WF-3: 毎朝の CEO Daily Digest(既存機能の統合)

```
[n8n] cron 6:00
→ 売上・予約・SNS指標・口コミを収集(Sheets/既存API)
→ [Router] COO Agent が日報生成(Sonnet)
→ 重要アラートがあれば CEO Agent(Fable 5)が打ち手を1つ提案
→ Obsidian(Daily Note)保存 + LINE 配信
```

### WF-4: 口コミ・DM 自動一次対応

```
[n8n] Google Business / Instagram webhook
→ [Router] Salon Agent が返信案を生成
→ 承認待ち(ネガティブ口コミは必ず人間承認)
→ 承認後に返信投稿 → Obsidian に記録
```

### WF-5: 競合ウォッチ(夜間・半額バッチ)

```
[n8n] cron 深夜
→ 競合SNS/サイトを収集
→ [Router] Batches API(50%オフ)で分析キュー投入
→ 翌朝、分析結果を Digest に合流
```

### WF-6: メール/カレンダー秘書(Phase: 社内AI秘書)

```
[n8n] Gmail/Calendar トリガー
→ [Router] 秘書処理(要約・返信案・予定調整案)
→ 承認 → 送信/登録 → Daily Note に記録
```

## 3. 共通設計

- **認証**: n8n → Router は署名付きヘッダ(`X-ROUTER-SECRET`)。Router → n8n も webhook secret
- **冪等性**: 全 webhook に `eventId` を付与し、二重実行を防止
- **失敗時**: n8n 側で3回リトライ → 失敗を Router にエラー報告 → Dashboard 表示 + LINE 通知
- **ホスティング**: n8n Cloud(手軽)or セルフホスト(Railway/VPS, 月$5〜)。**推奨: 初期は n8n Cloud Starter**

## 4. 実装順序

1. Day7: WF-2(SNS予約投稿)— 例Aパイプラインの出口として最初に必要
2. Day30: WF-1(音声→知識化)、WF-3(Daily Digest 統合)
3. Day90: WF-4(口コミ対応)、WF-5(競合ウォッチ)
4. Day180: WF-6(AI秘書)
