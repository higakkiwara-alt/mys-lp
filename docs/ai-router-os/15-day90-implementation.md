# 15. Day90 実装ドキュメント

**テーマ: AI COO を「自走する経営システム」に進化させる(品質・信頼性・学習能力)**
**最優先原則: AIが会社の知識・判断・改善を支え、人間が最終判断を行える状態を作る。**

## ① Reviewer Agent 強化 ✅

`lib/router/reviewer.ts` — 直近7日の実行ログを5軸で定量評価:

| 評価軸 | 集計内容 |
|---|---|
| 判断品質 | Fable使用理由の妥当性、オーナー却下・QA不合格の傾向 |
| コスト | 総額・モデル別内訳・**見積精度**(実測/見積の中央値。±30%超で見積テーブル補正を提案) |
| スピード | 平均/最大実行時間、**承認待ち滞留時間** |
| 再実行回数 | QA修正・オーナー却下・ステップエラーの件数と根本原因仮説 |
| 成功率 | done / 完了済み全体 |

毎週月曜 6:00 JST(GitHub Actions)に**「今週の改善提案」を自動生成** → Obsidian(`Logs/週次レビュー/`)保存 + Dashboard 表示(金枠セクション)+ LINE 報告。
ポリシー変更(Fable閾値等)は**提案まで**。適用はオーナーの承認が必要(Day90 原則)。データ不足時は無理に問題を作らず正直にそう書く設計。

## ② RAG 本格導入 ✅

`lib/obsidian/rag.ts` + `VaultIndex` テーブル:

- **インデックス**: Vault全ノートを差分同期(GitHub tree の sha 比較)し、OpenAI embeddings(text-embedding-3-small)でベクトル化。毎日 3:00 JST に自動同期(1回最大100件。初回は数日で全件到達 or 手動で複数回実行)
- **検索**: クエリ埋め込み × コサイン類似度 × **オーナー指定の優先順位の重み**:

```
CEO Principles(×1.3) → 会社方針・店舗ルール(×1.2) → 過去の判断(×1.15)
→ Meeting(×1.0) → Knowledge(×0.9) → Prompt(×0.8) → Archive(×0.5)
```

- ピン留めノート(CEO Principles)は検索と無関係に常時注入。インデックス未整備/OPENAI_API_KEY 無しの環境では従来の GitHub 検索に自動フォールバック

## ③ 動画ワークフロー ✅

`source=video` の依頼は一本化パイプライン:

```
動画(Google Drive 検知: WF-3) → 文字起こし(Whisper) → 知識化(主題・ノウハウ構造化)
→ 教材化(学習目標+ワーク+テスト) → SNS投稿(媒体別) → Shorts切り出し案3本(該当発言の特定つき)
→ YouTube最適化(タイトル/概要欄/チャプター/タグ/サムネ文言) → QA → Obsidian保存 → LINE報告
```

n8n テンプレート `wf-3-video-intake.json` 同梱(Driveフォルダ監視→Whisper→intake)。
**投稿は含まない**(禁止リスト遵守。すべて下書きとして保存)。

## ④ 不成約分析ワークフロー(SalesAnalyst 専用Agent)✅

BMU動画300本を資産化する専用Agent。商談・カウンセリング・不成約の依頼を自動検知:

```
分析(成約/不成約判定・決定的瞬間・理由を顧客の言葉で・反論と返答の評価・FAQ抽出
     ※過去の営業分析との共通パターンを RAG で参照)
→ 営業改善(トークBefore/After・構成変更・反論への先回り)
→ AIロールプレイ台本(顧客ペルソナ・分岐セリフ・合格基準・振り返り)
```

- 保存先: **`Company OS/営業分析/`**(分析が蓄積するほど次の分析が賢くなる = 会社の重要資産)
- 経営レベルの分析(complexity≥4)は analyze ステップのみ Fable 5 に昇格
- BMU動画は WF-3(動画入口)から `source=video` + 商談キーワードで流せば 分析パイプラインに乗る

## ⑤ 口コミ・クレームAgent(CS Agent)✅

```
口コミ/クレーム → 分類(感情・重大度・カテゴリ) → 会社方針参照(RAG: Company OS優先)
→ 返信案(見込み客向けの公開文章として) → 担当者向け改善案(根本原因・行動変更・SOP追記)
→ 教育コンテンツ化(匿名ケーススタディ・ロールプレイ設定・朝礼3分版) → QA → 承認待ち
```

**返信の送信は承認後も手動**(自動送信は禁止リスト。publish ステップなし)。

## ⑥ CEO Memory ✅

`CeoMemory` テーブル + `lib/router/ceo-memory.ts`:

- 経営・財務の判断が完了するたび、**背景/選択肢/決定/なぜ(reason)/何を優先したか(priorities)** を自動抽出して蓄積
- **結果の記録**: LINEで「`結果 <runId> 出店して3ヶ月で黒字化`」→ Memory + Obsidianノートに結果を追記
- **参照**: 次の経営判断時に、タグが近い過去の判断(決定・理由・優先・結果)を「過去の大竹一樹の判断」として自動注入。CEO Agent は整合性を確認し、矛盾する場合は指摘する
- → 「過去の大竹ならどう判断したか」を根拠(実際の判断記録+結果)付きで説明できる土台

## デプロイ時の追加作業

1. `npm run db:push`(VaultIndex / CeoMemory テーブル追加)
2. RAG初回インデックス: `curl -X POST <app>/api/router/vault-index -H "X-ROUTER-SECRET: ..."` をノート数に応じて数回(1回100件)
3. WF-0 を更新版(「結果」コマンド対応)に差し替え、WF-3(動画)をインポート(Drive フォルダID設定)
4. 週次レビューを試すなら手動で: `curl -X POST <app>/api/router/review -H "X-ROUTER-SECRET: ..."`

## 改善提案(開発ルール⑥)

1. **BMU動画300本の一括投入**: WF-3 は新規動画向け。過去動画300本はDriveフォルダに移すだけで順次処理されるが、コスト試算(300本 × 文字起こし$0.36 + 分析$0.3 ≈ **$200前後**)のため、10本で品質確認→承認→残りを夜間バッチ、の順を推奨
2. **CEO Memory の「結果リマインド」**: 判断から30日後に「結果はどうでしたか?」と LINE で自動確認する仕組み(Day180)
3. **Reviewer のポリシー自動適用**: 現在は提案のみ。3ヶ月分の提案・採否実績が貯まったら、低リスク項目(見積テーブル補正など)から自動適用を検討(Day180、監査ログ前提)
4. **Day180 に向けて**: 外部送信系(投稿API・メール)の解禁には サーバー認証・操作監査ログ・ロール権限 の3点セットが前提(オーナー方針どおり)
